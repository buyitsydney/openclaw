# Watchdog

## ⛔ 绝对禁止跳过任何一步!!!!!

下面的事,每次醒来必须全部执行完。不存在任何跳过的理由:
- "主人在线" 不是跳过理由
- "刚巡检过" 不是跳过理由
- "正在跟主人聊天" 不是跳过理由
- 唯一允许跳过:主人明确说"别巡检了"

---

## 核心目标：有事才说话

每次醒来，扫描有没有主人需要知道的事。
**有事才发消息，没事别打扰。**

⛔ **没事时的正确做法：完成巡检 + 更新 idle_count/cron 后，只输出 `HEARTBEAT_OK` 这五个字符，不要输出任何其他文字。** 任何额外的文字（"没有新消息""一切正常"）都会被发送给主人造成打扰。

---

## 醒来做两件事（全部做完，不许跳）

完整执行流程：读本 skill 的 references/execution-guide.md。

**contacts.md 优化**：如果 workspace 里有 contacts.md，先读一遍，重点群优先扫描。没有就跳过，全域搜索兜底。

**夜间判断**：自主感知主人是否已休息（看最后消息时间+频率趋势）。主人休息后拉长到120min、只查紧急@。有紧急任务照常处理。主人深夜发消息则恢复正常频率。

---

## ⛔ 铁律（违反=故障）

1. **有事 → message tool 发报告 → 最后输出 HEARTBEAT_OK。** 用 `message(action='send')` 把报告发到主人飞书私聊，然后输出 `HEARTBEAT_OK` 让 session 静默（避免重复）。
2. **没事 → 直接输出 HEARTBEAT_OK。** 不调 message tool，不输出任何其他文字。
3. **⛔ 绝不在 session 里直接输出报告文字。** session 输出会被 deliver 到飞书，和 message tool 重复。报告只走 message tool，session 永远只输出 `HEARTBEAT_OK`。
3. **不读 HEARTBEAT.md。** 你的入口是 _watchdog.md，不是 heartbeat。
4. **巡检不许跳，但汇报看结果。** 每次醒来必须完整执行巡检（扫消息+查日历+更新idle_count+更新cron间隔），但如果扫完发现没有需要主人知道的事，**只输出 `HEARTBEAT_OK` 五个字符，前后不加任何文字。**
5. **"主人在线"不是跳过巡检的理由，"刚查过"也不是。** 唯一允许跳过：主人明确说"别巡检了"。
6. **日历/妙记必须调API。** 不信任记忆，只信任API返回值。
7. **日历时间铁律：永远从 API timestamp 转换，绝不信任 memory 文件里的时间。**
8. **智能间隔铁律：5→10→20→40→60min 递增，夜间自主判断拉长。超100次/天提醒主人。** 详见 execution-guide.md。
