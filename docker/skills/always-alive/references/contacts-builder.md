# Contacts 建档流程

首次安装 watchdog 和主人说"更新通讯录"时执行。

## 1. 全域扫描（必须全部执行）

### 1a. 拉 bot 的群列表

调 `feishu_chat` 拿 bot 加入的所有群。记录：群名、chat_id、成员数、群主。

### 1b. 搜主人活跃的群

- 首选：`feishu_knowledge_qa(query="主人名字", sources=["message"])` — 找主人在哪些群发过言、被@过
- fallback（knowledge_qa 不可用时）：
  - `feishu_search` 搜主人名字
  - `feishu_message_search` 搜主人名字
- 目的：发现 bot 不在、但主人活跃的群

### 1c. 补充搜索（按需）

- 搜主人被@的记录：`feishu_knowledge_qa(query="@主人名字")` 或 `feishu_message_search`
- 搜 bot 被@的记录：发现哪些群在找 bot
- 如果发现主人有高频互动的私聊联系人，记录下来

## 2. 判断优先级

对每个群，综合以下信号判断优先级：

### 🔴 重点（满足任一即可）

- 主人是群主或管理员
- 主人近 7 天发言 ≥ 5 条
- 主人近 7 天被@ ≥ 3 次
- 群成员 ≤ 20 且信息密度高（核心项目群）
- bot 在群里且群里有人@bot

### 🟡 普通（满足任一）

- 主人偶尔发言（7 天内 1-4 条）
- 群 20-100 人，有与主人工作相关的话题
- bot 在群里但近期无人@

### ⚪ 低优先级（满足任一）

- 纯通知群/公告群（主人从不发言）
- 超大群（>100人）且主人近期无互动
- bot 不在群里且主人也不活跃

### 📱 重要联系人（满足任一）

- 近期频繁@主人的人
- 主人频繁私聊的人
- 群里主人经常回复的人

## 3. 生成 contacts.md

读取 `assets/contacts-template.md` 作为骨架，填入扫描结果：

- `{{date}}` 替换为当前日期
- 每个分类表格填入对应的群/联系人
- 判断理由要写清楚（"主人是群主"、"近7天被@8次"、"高频讨论项目X"）
- 写入 workspace `contacts.md`

## 4. 首次 vs 更新

**首次建档（安装时）：**

- 全新生成 contacts.md
- 首次报告语气："我帮你整理了通讯录，发现..."

**更新（主人说"更新通讯录"）：**

- 覆盖写入新的 contacts.md
- 报告变化："跟上次比，新增了X群，Y群从普通升为重点..."

**主人手动调整（"把XX群调到重点"等）：**

- 直接编辑 contacts.md 中对应行的分类
- 在判断理由列写"主人指定"
- 后续更新时保留主人手动调整的优先级，不覆盖
