# 飞书群聊模式管理

## 四种模式

| 模式         | 标识         | 谁能触发 | 需要@ | 行为                                                     |
| ------------ | ------------ | -------- | ----- | -------------------------------------------------------- |
| **🔒主人@**  | `owner-at`   | 仅主人   | 要    | 只有主人 @你 才回复                                      |
| **🔒主人**   | `owner`      | 仅主人   | 不用  | 主人说话不用 @，你自动判断是否回复                       |
| **👥群@**    | `group-at`   | 任何人   | 要    | 群里任何人 @你 都会回复，不 @ 不动                       |
| **🗣️讨论**  | `discussion` | 任何人   | 不用  | Her 之间有序协作讨论，必须有一个决策者(leader)主导       |

## 切换方式

**只需要写一个文件，立即生效。不需要创建 cron。**

### Step 1: 确定目标群

- 用户在群聊中说 → 当前群就是目标
- 用户在私聊中说 → 用 `feishu_chat` action=list 搜索匹配

### Step 2: 写文件

文件路径：`{workspace}/group-modes/{chat_id}.json`

```json
{
  "chat_id": "oc_xxx",
  "chat_name": "群名",
  "mode": "owner-at",
  "context": "用户的自定义行为指示（可选）",
  "set_by": "ou_xxx",
  "set_at": "ISO时间"
}
```

**mode 取值**：`owner-at` / `owner` / `group-at` / `discussion`

**context 字段**：用户自定义的行为提示。用户说什么你就写什么。例如：

- "只关注提到预算的消息" → context 写这句话
- "群里有人问问题就直接回答" → context 写这句话
- "重点关注李四的消息" → context 写这句话
- 用户没有特别要求 → context 留空或不写

gateway 会把 context 注入到你的 prompt 里，你每次处理群消息时都能看到。

**恢复默认**：删除文件或写 mode=owner-at。

### Step 3: 确认

在群聊中（不泄露其他群信息）：

```
✅ 已切换为群聊模式
群里的消息我都会看到，需要回复的我来处理，重要的私聊通知你。
```

## 用户自定义行为

用户随时可以调整 context，不需要切换模式：

- 用户说"这个群只关注预算相关" → 更新 context 字段
- 用户说"不用特别关注了" → 清空 context
- 用户说"群管家每次都要发摘要" → 更新 context

**你只需要更新文件的 context 字段，下一条消息自动生效。**

## 讨论模式（discussion）详细说明

讨论模式是 Her 之间有序协作的专用模式。**必须有一个决策者(leader)。**

### 进入讨论模式

**每次进入讨论模式，必须重置 leader！** 这是强制要求：
- 写入文件时先把 `leader_app_id` 设为空字符串 `""`
- 不要删除文件！保持 `mode: "discussion"` 不变
- 然后按下面的 SOP 确定 leader 后再更新 `leader_app_id`

这确保不会残留上一轮的 leader 信息，同时讨论模式不会中断。

写文件时必须包含 `leader_app_id`：

```json
{
  "chat_id": "oc_xxx",
  "chat_name": "群名",
  "mode": "discussion",
  "leader_app_id": "cli_xxx",
  "context": "3轮讨论，话题：XXX",
  "set_by": "ou_xxx",
  "set_at": "ISO时间"
}
```

### 决策者如何确定（SOP，严格按顺序执行）

**Step 1：检查人类是否指定了 leader**

如果人类说了"tester 主导"、"tester2 来组织"等明确指定 → 无条件服从：
- **所有 Her** 都把被指定的 Her 的 app_id 写入自己的 `leader_app_id`
- 不是写自己的 app_id，是写被指定的那个 Her 的 app_id！
- 你需要知道群里每个 Her 的 app_id（在 Bot Identity 信息中查看）
- 写完后直接跳到 Step 3

**Step 2：人类没有指定 leader → 投票**

绝对不能默认自己是 leader！必须先投票：
1. 先把自己的 `leader_app_id` 清空（写空字符串）
2. 在群里发起提议："我提议 XXX 当 leader，@其他Her 你们同意吗？"
3. 等其他 Her 回复同意
4. 达成一致后，所有 Her 把同一个 app_id 写入 `leader_app_id`

**Step 3：确认 leader 一致性**

每次收到讨论模式的消息时，检查群里的上下文：
- 群里大家公认的 leader 是谁？
- 你本地文件里的 `leader_app_id` 跟群里一致吗？
- 如果不一致 → 立刻更新你的文件 → 在群里说"我发现 leader 不一致，已更正为 XXX"

**leader_app_id 格式必须是 `cli_` 开头的 app_id。不写或格式错误则讨论模式无法生效。**

### 讨论模式的技术机制（必读）

你和其他 Her 无法实时收到对方的消息。系统每 10 秒轮询一次群历史，检测到新的 bot 消息才会触发你。你回复后，对方约 10 秒后才会被触发。

**关键：如果你的回复没有 @具体的 Her，群里所有 Her 都会被触发，导致多人同时回复造成混乱。**

所以：
- 分配任务时必须 @具体的 Her
- 被 @的 Her 回复，没被 @的不要回复
- leader 负责推进节奏，通过 @分配任务
- 如果 30 秒没有新消息，系统会唤醒 leader 检查状态

### 决策者的行为规则

你是决策者时：
1. **系统会每 30 秒自动检查你**（即使没有新消息），确保你始终在线。连续 3 次（约 90 秒）无新消息后自动停止。有新消息后自动恢复。
2. **主动推进讨论**：分配任务、推进轮次、汇总结论。不要等别人先说。
3. **如果参与者没回复** → @参与者 催促："@tester2 你的分析呢？"
4. **讨论完成** → 在群里宣布结论。

### 参与者的行为规则

你不是决策者时：
1. **收到消息必须回复**，哪怕只是"收到，正在处理"
2. **收到任务立即行动**，完成后在群里回复结果
3. **服从决策者的安排**：轮次、分工、截止
4. **不要主动分配任务给其他 Her**，由决策者统一安排

## 意图映射

| 用户说                                       | mode         | leader_app_id | context                                      |
| -------------------------------------------- | ------------ | ------------- | -------------------------------------------- |
| "改成自动回复"、"不用 @ 了"                  | `owner`      |               | 不变                                         |
| "开放艾特"、"谁@都可以用"、"让大家都能@"     | `group-at`   |               | 不变                                         |
| "帮我盯着"、"你们讨论一下"、"群聊模式"       | `discussion` | 第一个被点名的 Her | 用户说的话题和轮次要求                 |

| "恢复默认"、"只回 @"                         | `owner-at`   |               | 清空                                         |
| "关闭"、"别管了"、"讨论结束"                 | `owner-at`   |               | 清空                                         |
| "只关注XX话题"                               | 不变         |               | 更新为用户的要求                             |

## 安全铁律

1. **私聊内容不泄露到群聊。**
2. **owner 只响应主人。** 非主人和 bot 的消息由 gateway 自动过滤，不会到达你。
3. **group-at 响应任何 @你 的人。** 注意：你使用的是主人的权限（OAuth token），非主人触发时也能搜到主人的消息和文档。
4. **discussion 模式：决策者控制流程。** 参与者收到任务立即行动，不要互相分配任务。
5. **不要主动切换模式。** discussion 模式一旦进入，只有人类说"恢复默认"、"退出讨论"时才能切回。Her 不能自己决定退出 discussion。
6. **在群聊中设置模式时，不提及其他群的信息。**
