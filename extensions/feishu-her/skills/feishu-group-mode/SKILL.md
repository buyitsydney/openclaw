# 飞书群聊模式管理

## 四种模式

| 模式        | 标识         | 谁能触发 | 需要@ | 行为                                             |
| ----------- | ------------ | -------- | ----- | ------------------------------------------------ |
| **🔒主人@** | `owner-at`   | 仅主人   | 要    | 只有主人 @你 才回复                              |
| **🔒主人**  | `owner`      | 仅主人   | 不用  | 主人说话不用 @，你自动判断是否回复               |
| **👥群@**   | `group-at`   | 任何人   | 要    | 群里任何人 @你 都会回复，不 @ 不动               |
| **🗣️讨论**  | `discussion` | 任何人   | 不用  | Her 之间有序协作讨论，系统自动选举决策者(leader) |

## 切换方式

**只需要写一个文件，立即生效。不需要创建 cron。**

### Step 1: 确定目标群

- 用户在群聊中说 → 当前群就是目标
- 用户在私聊中说 → 用 `feishu_chat` action=list 搜索匹配

### Step 2: 写文件

文件路径：`{workspace}/group-modes/{chat_id}.json`

```json
{
  "chat_id": "oc_xxx",
  "chat_name": "群名",
  "mode": "discussion",
  "context": "用户的自定义行为指示（可选）",
  "set_by": "ou_xxx",
  "set_at": "ISO时间"
}
```

**mode 取值**：`owner-at` / `owner` / `group-at` / `discussion`

**context 字段**：用户自定义的行为提示。用户说什么你就写什么。

**禁止写 `leader_app_id` 字段！** leader 由系统通过 Redis 自动选举，不在文件中。

**恢复默认**：删除文件或写 mode=owner-at。

### Step 3: 确认

在群聊中（不泄露其他群信息）：

```
✅ 已切换为讨论模式
系统会自动选举决策者，讨论即将开始。
```

## 用户自定义行为

用户随时可以调整 context，不需要切换模式：

- 用户说"这个群只关注预算相关" → 更新 context 字段
- 用户说"不用特别关注了" → 清空 context
- 用户说"3轮讨论" → 更新 context

**你只需要更新文件的 context 字段，下一条消息自动生效。**

## 讨论模式（discussion）详细说明

### leader 如何确定（系统自动，不需要你操作）

1. **系统默认**：进入讨论模式后，系统自动选举 appId 最小的参与 bot 为 leader。100% 确定性，无需投票。
2. **人类指定**：如果人类明确说"@tester2 你来主导"，被指定的 bot 使用 `set_discussion_leader` 工具更新 leader。
3. **你不需要写文件来设定 leader。** 不要在 group-modes 文件中写 `leader_app_id`。

### 何时调用 set_discussion_leader 工具

**只在人类明确指定你为新主导者时才调用**：

- "你来主导" / "你负责" / "你当 leader" / "你来带" → **调用**
- "你觉得呢" / "你怎么看" / "说说你的想法" → **不调用**（这是提问，不是指定 leader）
- 如果不确定 → **不要调用**

调用方式：

```
set_discussion_leader(chat_id="oc_xxx", leader_app_id="你自己的app_id")
```

### 讨论模式的技术机制（必读）

bot 之间会通过系统广播几乎实时看到彼此的群消息，但这些消息默认只是上下文，不等于真正唤醒对方。

**关键：只有显式 `@` 到某个 Her，才表示你希望它真正接手这一轮。**

如果你没有显式 `@` 对方，那么像“等 tester”“你来补充”“该你了”这类表述默认都只算 context，不保证对方会被唤醒。

这样设计是为了避免误触发、重复响应、上下文膨胀和无效 token 消耗。

### 决策者的行为规则

你是决策者时（系统会在 context 中告诉你"你是主导者"）：

1. **主动推进讨论**：分配任务、推进轮次、汇总结论。不要等别人先说。
2. **如果参与者没回复** → @参与者催促。
3. **讨论完成** → 在群里宣布结论。

### 参与者的行为规则

你不是决策者时（系统会在 context 中告诉你"你是参与者"）：

1. **被 @时回复**，给出你的观点。
2. **服从决策者的安排**：轮次、分工、截止。
3. **不要主动推进讨论节奏**，由决策者统一安排。

## 意图映射

| 用户说                                   | mode         | context                |
| ---------------------------------------- | ------------ | ---------------------- |
| "改成自动回复"、"不用 @ 了"              | `owner`      | 不变                   |
| "开放艾特"、"谁@都可以用"、"让大家都能@" | `group-at`   | 不变                   |
| "你们讨论一下"、"群聊模式"、"进入讨论"   | `discussion` | 用户说的话题和轮次要求 |
| "恢复默认"、"只回 @"                     | `owner-at`   | 清空                   |
| "关闭"、"别管了"、"讨论结束"             | `owner-at`   | 清空                   |
| "只关注XX话题"                           | 不变         | 更新为用户的要求       |

## 安全铁律

1. **私聊内容不泄露到群聊。**
2. **owner 只响应主人。**
3. **group-at 响应任何 @你 的人。** 注意：你使用主人的权限。
4. **discussion 模式：服从系统角色分配。** 系统告诉你是 leader 就主导，告诉你是参与者就配合。
5. **不要主动切换模式。** 只有人类说"恢复默认"时才切回。
6. **在群聊中设置模式时，不提及其他群的信息。**
7. **禁止在 group-modes 文件中写 leader_app_id 字段。** leader 由系统管理。
