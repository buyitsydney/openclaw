# 飞书群聊模式管理

## 三种模式（2+1）

| 模式        | 标识         | 谁能触发 | 需要@ | 行为                                             |
| ----------- | ------------ | -------- | ----- | ------------------------------------------------ |
| **🔒主人@** | `owner-at`   | 仅主人   | 要    | 只有主人 @你 才回复（安全默认）                  |
| **👥群@**   | `group-at`   | 任何人   | 要    | 群里任何人 @你 都会回复，不 @ 不动               |
| **🗣️讨论**  | `discussion` | 任何人   | 不用  | Her 之间单 owner 接力讨论，leader 负责控场与分配 |

**注意**：旧的"主人模式"（`owner`）已移除，已有配置自动回退到 `owner-at`。

## 切换方式

**只需要写一个文件，立即生效。不需要创建 cron。**

### Step 1: 确定目标群

- 用户在群聊中说 → 当前群就是目标
- 用户在私聊中说 → 用 `feishu_chat` action=list 搜索匹配

### Step 2: 写文件

文件路径：`{workspace}/group-modes/{chat_id}.json`

```json
{
  "chat_id": "oc_xxx",
  "chat_name": "群名",
  "mode": "group-at",
  "context": "用户的自定义行为指示（可选）",
  "set_by": "ou_xxx",
  "set_at": "ISO时间"
}
```

**mode 取值**：`owner-at` / `group-at` / `discussion`

**context 字段**：用户自定义的行为提示。用户说什么你就写什么。

**禁止写 `leader_app_id` 字段！** leader 由系统通过 Redis 自动选举，不在文件中。

**恢复默认**：删除文件或写 mode=owner-at。

### Step 3: 确认

在群聊中（不泄露其他群信息）：

```
✅ 已切换为群@模式
群里任何人 @我 都会回复。
```

## 意图映射

### 群@模式（默认群聊模式）

用户说"群聊模式"、"开放艾特"、"谁@都可以用"、"让大家都能@" → **写 mode=`group-at`**

**这是群聊场景的默认推荐模式。** 当用户泛泛说"群聊模式"、"打开群聊"时，就切到 `group-at`。

### 讨论模式（强关键词匹配）

**必须用户消息中包含"打开讨论模式"这四个字才切换到讨论模式。**

以下表达**不触发**讨论模式：
- "讨论一下" → 不触发（太模糊）
- "你们聊聊" → 不触发
- "进入讨论" → 不触发
- "协作模式" → 不触发
- "群聊模式" → 切到 group-at，不是讨论模式

以下表达**触发**讨论模式：
- "打开讨论模式" → 触发
- "请打开讨论模式" → 触发
- "帮我打开讨论模式" → 触发
- "打开讨论模式，话题是XXX" → 触发，context=话题

**判断规则：消息文本中必须包含连续的"打开讨论模式"五个字。** 不要拆分匹配，不要模糊匹配。

### 恢复默认

用户说"恢复默认"、"只回 @"、"关闭"、"别管了" → **写 mode=`owner-at`，清空 context**

### 更新上下文

用户说"只关注XX话题"、"3轮讨论" → **只更新 context 字段，不改 mode**

| 用户说                                       | mode         | context                |
| -------------------------------------------- | ------------ | ---------------------- |
| "群聊模式"、"开放艾特"、"谁@都可以用"        | `group-at`   | 不变                   |
| "打开讨论模式"                               | `discussion` | 用户说的话题和轮次要求 |
| "恢复默认"、"只回 @"、"关闭"、"别管了"       | `owner-at`   | 清空                   |
| "只关注XX话题"                               | 不变         | 更新为用户的要求       |

## 用户自定义行为

用户随时可以调整 context，不需要切换模式：

- 用户说"这个群只关注预算相关" → 更新 context 字段
- 用户说"不用特别关注了" → 清空 context
- 用户说"3轮讨论" → 更新 context

**你只需要更新文件的 context 字段，下一条消息自动生效。**

## 讨论模式（discussion）详细说明

### 核心体验规则（本节最重要）

1. **任意时刻只允许一个 current owner 在群里公开发言。** 不要让多个 Her 同时输出。
2. **leader / chair 负责控场，但不等于每一轮都要亲自发言。** 只有当系统把 owner 交给 leader 时，leader 才公开说话。
3. **人类消息优先级最高。** 人类 `@bot` 时，被 `@` 的 bot 直接回复人类，不影响正在进行的讨论轮次。讨论 turn 继续正常流转。
4. **非当前 owner 默认只旁听。** 即使正文里出现了你的名字或 `@你`，也不要擅自插话，除非系统已经把这一棒明确交给你，或人类明确 `@` 了你。
5. **如果当前 owner 需要别人参与，只允许两种推进方式**：
   - 请求 leader / chair 重新分配下一棒
   - 明确把下一棒交给唯一一个 owner
6. **每个 owner 在本轮发言结束时，必须用一句简短的话说明下一棒交给谁。**
7. **这句公开说明必须与系统实际调度的下一棒 owner 完全一致。** 不要口头说 A，实际把 turn 给 B。
8. **如果当前轮次还没有完成系统调度，就不要提前公开宣布下一棒。**
9. **如果你在公开消息里同时 `@` 多个 bot，系统会采用 first-win：只把下一棒交给第一个被 `@` 的 bot。** 不会再回落到没被 `@` 的 bot。

### leader 如何确定（系统自动，不需要你写文件）

1. **系统默认**：进入讨论模式后，系统自动选举 appId 最小的参与 bot 为 leader。100% 确定性，无需投票。
2. **人类指定**：如果人类明确说"@tester2 你来主导"，被指定的 bot 使用 `set_discussion_leader` 工具更新 leader。
3. **你不需要写文件来设定 leader。** 不要在 group-modes 文件中写 `leader_app_id`。

### 何时调用 discussion lifecycle tools

**讨论的结束/重开只认显式 tool，不认自然语言：**

- 要结束当前讨论 → 调用 `end_discussion`（清空队列，不再自动分配下一棒，但你仍可以发送最后的总结）
- 要清空旧队列并重开新一轮 → 调用 `reset_discussion`（如果话题变了，**必须传 `context` 参数**写入新话题）
- 只是换 leader / chair → 调用 `set_discussion_leader`

### 何时调用 set_discussion_leader 工具

**只在人类明确指定你为新主导者时才调用**：

- "你来主导" / "你负责" / "你当 leader" / "你来带" → **调用**
- "你觉得呢" / "你怎么看" / "说说你的想法" → **不调用**（这是提问，不是指定 leader）
- 如果不确定 → **不要调用**

调用方式：

```
set_discussion_leader(chat_id="oc_xxx", leader_app_id="你自己的app_id")
```

### 何时调用 end_discussion / reset_discussion

- 人类明确要求"结束讨论 / 收官 / 到此为止" → **调用 `end_discussion`**
- 人类明确要求"重开一轮 / 清空旧队列重新开始 / 换新 leader 重新来" → **调用 `reset_discussion`**（新话题时传 `context` 参数）
- 人类抛出新话题，当前讨论应当切换 → leader **调用 `reset_discussion` 并传 `context` 参数为新话题**
- 只是普通追问、补充观点、问你怎么看 → **不要调用**

### 话题（context）更新规则

**话题由 `group-modes/{chat_id}.json` 的 `context` 字段驱动，dashboard 实时读取并显示。**

- 进入讨论模式时：在文件里写 `context`（用户说的话题）
- 讨论中途换话题：leader 调用 `reset_discussion` 时**必须传 `context` 参数**，工具会自动更新文件
- 不要在讨论进行中手动写文件来更新话题，统一通过 `reset_discussion` 的 `context` 参数

### mode / turn 不是一回事

- `discussion` mode 是群级长期策略，写在 `group-modes/{chat_id}.json` 里。它决定这个群是否使用讨论协议。
- `turn` 是 Redis 里的单轮发言权，任意时刻只属于一个 current owner。没有 turn 时讨论处于空闲，下一次人类发消息可以启动新一轮。
- `end_discussion` 只会清空当前 turn 的后续队列（不再自动分配下一棒），不会把群模式切出 `discussion`。后续人类再发消息可以开始新一轮。
- `reset_discussion` 会丢弃旧队列，并开启一个**新的 epoch**。所以它不是"补一句话"，而是"丢弃旧运行态，重新开局"。

### leader / chair 的行为规则

你是 leader / chair 时：

1. **负责控场，不必每轮亲自发言。** 你的首要职责是确定谁是当前 owner、是否需要追加轮次、何时收官。
2. **任何时候都只保留一个公开 owner。** 不要安排两位 Her 同时在群里输出。
3. **如果 owner 请求你重新分配下一棒**，你要快速给出唯一的下一位 owner。
4. **需要收官时**，调用 `end_discussion`。之后你仍可以发送最后的公开总结（turn 不会立即消失，只是队列被清空）。
5. **需要重新开始时**，调用 `reset_discussion`，不要试图靠普通中文硬切状态。

### current owner 的行为规则

你是当前 owner 时：

1. **你是本轮唯一允许公开发言的人。**
2. **如果需要其他 Her 参与**，优先请 leader / chair 分配；如果你已经明确知道下一棒是谁，只交给唯一一个 owner。
3. **本轮最后一句必须简单说明下一棒是谁**，例如：
   - `下一棒交给 tester3。`
   - `这一轮请 leader 接手分配下一棒。`
   - `讨论已充分，下一棒请 leader 收官。`
4. **不要同时把下一棒交给多个人。**
5. **不要让你的正文说明和系统调度结果不一致。**

### 参与者的行为规则

你不是当前 owner 时：

1. **默认旁听**，等待 leader / system 明确把下一棒交给你。
2. **不要因为正文里出现你的名字或普通 `@` 就自动开口。**
3. **如果人类明确 `@` 了你**，你直接回复人类的消息，不需要等待 turn 分配。讨论轮次不受影响。
4. **如果你被 leader 或当前 owner 明确指定为下一棒**，再在你的回合里发言。

## 安全铁律

1. **私聊内容不泄露到群聊。**
2. **owner-at 只响应主人 @。**
3. **group-at 响应任何 @你 的人。** 注意：你使用主人的权限。
4. **discussion 模式：服从系统角色分配。** 系统告诉你是 leader 就主导，告诉你是参与者就配合。
5. **不要主动切换模式。** 只有人类明确要求时才切换。
6. **在群聊中设置模式时，不提及其他群的信息。**
7. **禁止在 group-modes 文件中写 leader_app_id 字段。** leader 由系统管理。
